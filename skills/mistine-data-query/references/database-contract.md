# 素材事实、去重与 ROI 核验

## 事实层不能混加

| 数据层 | 可用粒度和用途 | 禁止做法 |
| --- | --- | --- |
| 微信豆 `fact_material_daily` | 带采集账号的分析页原始观察，保留追溯 | 跨 account_key 直接 SUM 后称业务总额 |
| 微信豆 `v_material_daily_deduplicated` | 经核实的同一业务主体内，日期 × 长素材ID × 平台直播间ID × 平台创建人ID × order_class × 场次ID | 按昵称、短标题、金额相等去重；简单除二 |
| 微信豆计划素材分析 | 日期 × 计划 × 素材的独立事实链，需检查采集组合与订单类型是否重叠 | 与素材分析页相加；默认覆盖所有计划 |
| 微信豆订单详情 | 订单/长期计划 × 视频素材，先核验素材合计与整单金额 | 将整单 GMV 复制给每条素材；将累计值铺到每日 |
| ADQ `video_daily` | 日期 × 实际消耗账户 × 素材ID | 因共享同一云视频而删掉另一账户真实消耗 |
| 映射、审核、推送 | 维度与关联证据 | 将一对多明细直接 JOIN 消耗再 SUM |

## 微信豆标准规则 v1

1. 只合并已验证属于同一业务主体的采集上下文。账号名称仅用于服务端已核实的业务范围配置，不用来代替素材、创建人或直播间的稳定平台 ID。新业务主体/未知登录范围需要单独验证后加入，不能跨主体去重。
2. 主账号和员工分身可以查看相同平台数据，不存在据此认定的“员工独有业务消耗”。数据库只在某个上下文保存了记录，表示已落库快照不一致，需检查采集时间、日期、筛选、分页与失败记录；不能推断平台权限不同。历史快照一并纳入候选并按完整业务键去重，不用单个不完整采集快照冒充全历史。
3. 同键按 `last_captured_at DESC, daily_key DESC` 取一整行。不能对消耗、GMV 分别取 MAX，也不能取最新非零值覆盖新返回的零。
4. 关键身份缺失时保留记录并计入 `unresolved_identity_rows`，不把多个未知身份强行合并。该值非零时金额仍需核验，不称最终确认。无场次维度的素材日汇总与有场次数据应分别核查，不能将聚合层和子层相加。
5. 公共接口先筛选日期/稳定素材ID以缩小候选，完成去重后再筛选创建人昵称、上传人、直播间资料。昵称变更不能让旧快照重新进入合计。
6. `dim_author_profile` 等只用于筛选的关联使用 EXISTS，避免一对多放大消耗。其他映射必须先确认每个事实键最多一行。

接口返回 `source_observation_rows`、`canonical_fact_rows`、`duplicate_observations_removed`、`unresolved_identity_rows`、实际日期与 `data_cutoff`。前两者之差应等于去除的重复观察数；`count` 是返回的素材数，不是底层事实数。默认行数限制不能当完整总计，达到 limit 时必须继续拆分查询并检查覆盖。

数据库原始表保留，不删除“重复观察”。旧 `v_material_daily_canonical` 仅主账号的历史定义不能替代 v1 新视图。旧版客户端无法阻止任意 SQL；直接查库的使用者也必须遵守本契约。

## ROI 和历史范围

- 素材分析页可能返回历史消耗但成交为零；零不能自动认定没有真实成交。`roi_basis=analysis_page_not_reconciled_order_details` 明确表示尚未与订单详情核对，去重成功不等于最终 ROI 已核实。
- 按用户要求以订单详情为准时，先验证同一业务主体、唯一订单/计划ID、视频素材类型、最新快照、已结束状态及素材合计/整单差额。`materialType=1` 可能携带整单成交，不能无差别累加；类型须按接口定义验证。
- ROI = 同口径汇总成交额 ÷ 同口径汇总消耗，净 ROI 使用净成交额；单位为倍数。不能把分析页消耗与另一时间范围/覆盖范围的订单成交额拼成 ROI。
- 整单累计值不是逐日值。没有可靠的订单素材日明细时，改报生命周期/订单口径，不能按消耗比例虚构每日成交。
- 查询范围、“实际有记录的首末日”、每行采集时间、结束订单筛选及缺失覆盖分别列出。仅有全库最早/最晚日期不证明每条素材全生命周期完整。
- 微信豆金额已是元；ADQ 源为分、CLI 为元。共享素材的归属账户只补身份，不改变消耗归属。

## 交付前最低核验

固定同一日期和快照，抽查重复业务键的源记录与最新整行，核对 JOIN 前后行数/金额；检查只被部分采集快照保存的历史不丢失、不同订单类型/创建人不误合并、真实 ADQ 多账户消耗仍相加。查询公共 API 验证契约及金额，不能用本地代码或文档变更代替已部署证明。出现差异先撤回未核验确定值，保留失败证据，不猜最终数字。
